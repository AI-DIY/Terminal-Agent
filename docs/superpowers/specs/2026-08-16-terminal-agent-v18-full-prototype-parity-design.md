# Terminal-Agent V18 原型完整功能对齐设计规格

> 文档状态：产品基线已确认，等待用户核对中文实施规格
>
> 产品唯一基准：.superpowers/brainstorm/ui-20260811185554/content/simplified-core-workbench-v18-unified-ssh-connection.html
>
> 本文档取代 2026-08-15-terminal-agent-v18-unified-ssh-integration-design.md 中对实施范围的错误限制。V18 原型是功能和视觉验收基准；现有 Vue/Electron 实现仍是安全边界与向后兼容基准。

## 1. 目标

在真实的 Terminal-Agent 应用中实现 V18 原型的全部功能，而不是只应用三栏外壳和统一 SSH 连接入口。

最终应用必须为原型中的每个交互区域提供真实行为：

1. 左侧聊天会话导航与历史回放；
2. 中间多 Shell 画布；
3. 右侧全局 AI 聊天、上下文管理、多主机命令审批和驾驶模式；
4. 设置中的六个完整功能区域；
5. V18 已引入的四种 SSH 连接方式；
6. 上述功能对应的本地持久化、重启恢复、参数校验、安全 IPC 和错误状态。

原型里的示例聊天、主机、命令历史、模型配置和主机记忆不能作为伪造的产品数据写入应用。生产界面必须显示真实持久化数据；没有数据时显示真实空状态。

## 2. 不可破坏的现有能力

完整对齐过程中必须保留以下已有功能：

- 用户名密码 SSH 和私钥 SSH，包括 .ppk 转换与私钥密码短语；
- 已保存直连会话以及受保护的凭据；
- 与 AccessClient/Assess 兼容的启动参数，包括 @saved、-load、-raw 和第二实例唤起；
- 安装包中的 putty.exe 桥接程序及现有安装行为；
- xterm 输入、输出、尺寸同步、缓冲区和会话隔离；
- 辅助驾驶确认、全自动执行、正则安全围栏和敏感信息脱敏；
- 主机只读观察及现有主机事实仓库；
- 所有 renderer 到主进程 IPC 的可信发送方校验；
- 进入设置页时不销毁已经挂载的实时终端；
- V18 统一 SSH 入口及其四种连接方式。

任何原型功能都不能通过“用 renderer 演示状态替换真实后端”的方式实现。

## 3. 完整功能覆盖矩阵

### 3.1 应用外壳

| 原型行为 | 生产实现 |
| --- | --- |
| 顶部品牌与当前聊天标题 | 显示当前持久化聊天标题；AI 生成标题后同步更新 |
| 打开设置/返回工作台 | 延续现有视图保持策略，使 SSH 和 AI 流在设置页期间继续运行 |
| 收起/展开左右面板 | 保存为用户布局偏好；收起不会卸载终端或聊天状态 |
| 可拖动分隔条 | 支持鼠标和键盘调整宽度，应用最小/最大限制并持久化 |
| 珍珠白与石墨黑主题 | 保存真实主题，并在应用首次绘制前恢复，避免闪烁 |

### 3.2 左侧聊天会话区域

| 原型行为 | 生产实现 |
| --- | --- |
| 新建聊天 | 创建持久化聊天工作区，初始标题使用带时间的后备标题 |
| AI 自动生成标题 | 第一次成功的 AI 回复可以生成简短标题；失败时保留后备标题 |
| 按日期分组 | 根据真实创建时间计算“今天/具体日期/更早”分组 |
| 每个聊天的 Shell 数量 | 根据聊天与 Shell 的真实关联记录计算 |
| 选择当前或历史聊天 | 原子切换聊天消息、Shell 关联、活动 Shell 和右侧显示模式 |
| 历史聊天回放 | 恢复已关闭 Shell 的只读输出快照以及对应 AI 执行记录 |
| 返回实时聊天 | 恢复仍在运行的 Shell 画布，不覆盖终端缓冲区和布局 |
| 空状态与加载状态 | 来自真实仓库状态，不注入原型示例数据 |

聊天工作区与“已保存 SSH 会话”是两类不同的数据。一个聊天可以关联多个正在运行、已经断开或仅保留历史记录的 Shell。

### 3.3 中间 Shell 画布

| 原型行为 | 生产实现 |
| --- | --- |
| 主机标签 | 显示当前聊天关联的真实实时/历史 Shell 及连接状态 |
| 选择和关闭标签 | 聚焦或关闭真实会话；历史标签保持只读 |
| 主机右键菜单 | 复制 SSH 通道、重新连接断开的主机、查看 Shell 历史 |
| 布局菜单 | 设置当前展示数量、每行数量和单行高度，并持久化 |
| 多面板画布 | 显示所选 Shell 子集；隐藏的终端保持挂载，不被销毁 |
| 终端历史按钮 | 打开该主机真实历史列表和只读终端预览 |
| 最大化/恢复 | 在工作台内部最大化一个终端，并恢复此前网格 |
| 关闭 | 关闭实时会话并处理失败；历史面板只从当前视图移除 |
| 复制通道 | 复用可重连配置或主进程连接描述，不把凭据复制到 renderer |
| 重新连接 | 使用安全的已有连接描述建立真实新会话并记录关联 |
| 无 Shell 空状态 | 显示同一套 V18 四方式 SSH 连接入口 |

终端输出经过敏感信息策略检查后，以有上限的历史记录持久化。会话在线时以实时 xterm 缓冲区为准；持久化快照只用于历史回放。

### 3.4 统一 SSH 连接

中间空状态和已有 Shell 后的连接入口都提供：

1. 堡垒机 CMDB 唤起；
2. 堡垒机精确主机唤起；
3. 主机用户名与密码 SSH；
4. 主机私钥 SSH。

继续执行已经实现的 V18 规则：

- 不写入虚假的 CMDB 系统或主机；
- 没有堡垒机目录提供方时显示明确的不可用状态；
- 堡垒机主机方式必须校验完整目标；
- 已打开的 CMDB 目标只聚焦已有会话，不重复连接；
- 切换连接方式或关闭对话框时清理敏感直连字段；
- 只有密码和私钥直连可以保存到 SSH 会话簿；
- 连接失败不关闭入口，也不清除非敏感输入。

连接成功后，默认把新 Shell 关联到当前实时聊天。

### 3.5 右侧全局 AI 聊天

右侧面板改为“聊天级、可感知多个 Shell”的全局 AI，而不是只服务于单个活动终端的简单表单。

必须实现：

- 点击发送按钮或按 Ctrl+Enter 发送，并正确处理中文输入法组合状态；
- 用户和 AI 消息流式写入当前持久化聊天；
- 模型上下文包含当前聊天、全部关联实时 Shell 的安全元数据、允许使用的主机事实和近期已批准执行结果；
- 历史聊天只读显示持久化消息与执行记录；
- 网络或模型错误生成可重试的 AI 错误记录，不丢失用户消息；
- AI 流式响应期间切换聊天，不能把增量写入错误聊天；
- 只有用户明确取消或删除聊天时才取消请求，普通面板切换不取消；
- 所有内容以纯文本或经过净化的 Markdown 显示，绝不直接渲染模型返回的任意 HTML。

迁移期间保留现有单会话 AgentPanel 调度器作为兼容适配器。新的全局聊天服务负责协调一个或多个目标 Shell，并发送带聊天标识的事件流。

### 3.6 驾驶模式

驾驶模式归属于当前聊天，与原型一致：

- copilot（辅助驾驶）：生成的命令必须经过明确批准；
- autonomous（全自动驾驶）：命令通过全部本地安全围栏后可以自动执行；
- 切换为全自动驾驶前必须显示原型中的确认对话框；
- 模式随聊天持久化，但新建聊天默认恢复为辅助驾驶；
- 关闭或切换单个 Shell 不会重置聊天驾驶模式；
- 全自动驾驶不能绕过正则围栏、可信 IPC、目标校验和敏感信息脱敏。

### 3.7 上下文用量与压缩

上下文用量必须来自真实估算，不能继续使用原型中的固定数字。

- used 根据即将发送给模型的聊天与上下文内容估算；
- total 来自当前激活模型配置的上下文长度；
- 消息、主机事实或执行记录变化后更新进度条和百分比；
- 手动压缩把符合条件的旧消息替换为持久化摘要，同时保留近期消息和全部命令审计；
- 达到 90% 阈值时，在请求超过模型上限前自动压缩；
- 保存最近压缩时间以及“手动/自动”类型；
- 压缩失败时保留原始聊天，不写入半成品摘要，并显示可重试错误。

首版可使用确定性的字符估算器。估算器必须隔离在接口之后，便于以后替换成模型供应商专用 tokenizer。

### 3.8 多主机命令计划和审批

AI 输出可以包含零个或多个按主机划分的候选命令。每条候选命令包含稳定的候选 ID、聊天 ID、目标会话 ID、命令和解释。

辅助驾驶行为：

- 在一张审批卡中展示全部目标；
- 批准前允许分别编辑每台主机的命令；
- 编辑后命令不能为空，且不能更换绑定目标；
- 批准时逐条执行确认和安全围栏检查；
- 只执行通过的命令，按主机展示被拦截或失败结果；
- 拒绝时记录审计结果，不向任何 Shell 发送命令；
- 重复点击必须幂等，不能让同一候选命令执行两次。

全自动驾驶行为：

- 隐藏编辑和批准/拒绝操作；
- 对每条候选命令执行同一套安全围栏；
- 执行允许的命令，并逐条显示被拦截的命令；
- 多主机部分失败时不得显示整体成功。

所有审批决定和终端执行结果都追加到当前聊天历史。

### 3.9 Shell 历史和聊天回放

每个关闭或断开的 Shell 生成一条有上限的历史记录，包括：

- 稳定历史 ID 和聊天 ID；
- 主机显示身份、开始/结束时间和连接类型；
- 脱敏后的终端输出快照；
- 与该 Shell 关联的命令执行审计；
- 可用时保存不含原始凭据的重连描述引用。

历史对话框支持选择记录并预览。选择历史聊天时，中间显示关联主机的最近 Shell 历史，右侧显示对应 AI 记录。执行重新连接后返回实时工作区，创建真实新会话，并把新会话关联到该聊天。

保留记录数和单条输出大小都必须有上限；写入必须原子化并串行排队，避免数据损坏。

## 4. 设置功能完整对齐

设置页包含原型中的六个导航项目，并提供真实保存和测试行为。

### 4.1 模型选择

- “大语言模型 + 视觉语言模型”：激活的 LLM 负责聊天、规划和 Shell 调度；遇到图像时调用激活的 VLM；
- “视觉语言模型”：激活的 VLM 同时处理文本和图像请求；
- 选择结果持久化，并由全局聊天路由真实使用；
- 保存失败时不改变运行中的模型路由。

### 4.2 大语言模型连接

- 支持列出、新建、编辑、测试、保存、激活和删除多个 LLM 配置；
- 支持 OpenAI 兼容 chat/completions、Ollama Chat 和 llama.cpp OpenAI 兼容接口；
- 字段与原型一致：连接名称、接口类型、模型、接口地址、上下文长度、API Key；
- 列表非空时最多只能激活一个配置；
- 新配置默认不激活，但第一个有效配置可以自动成为激活项；
- 删除激活项时必须选择替代项，或明确进入“没有可用路由”状态；
- API Key 只保存在操作系统受保护的密钥仓库中，绝不返回 renderer。

### 4.3 视觉语言模型连接

- 使用独立的 VLM 配置列表，支持新建、编辑、测试、保存、激活和删除；
- 字段与原型一致：连接名称、接口类型、模型、接口地址、最大图像数量、API Key；
- 可以显式引用某个 LLM 密钥，但不能把明文密钥复制到 renderer 或设置 JSON；
- 存在可用配置时最多只能激活一个 VLM。

### 4.4 安全围栏

现有正则围栏引擎继续作为唯一执行依据。页面支持：

- 启用/停用、编辑规则名、编辑正则、新增、删除、测试和保存；
- 就地显示无效正则错误；
- 测试器按确定顺序显示第一条命中规则；
- 只有全部启用规则有效时才能原子保存；
- 保存后立即应用到新的命令执行请求。

### 4.5 本地主机记忆

- 全局启用/关闭开关；
- 原型中的四类采集范围复选框；
- 首次连接新主机时先显示信息告知，再开始采集；
- 列出真实缓存主机、最近更新时间和摘要；
- 展开/收起真实结构化事实；
- 编辑并保存允许修改的非敏感事实；
- 清除单台主机记忆；
- 关闭功能只停止后续观察持久化，不自动删除已有记录；
- 不保存密码、私钥、API Key、令牌、环境变量值和完整终端内容。

现有主机事实结构需要扩展为可安全向 renderer 提供列表、更新、删除、全局配置和告知状态。只使用 IP 连接时先保留稳定连接身份，观察到真实主机名后才保存事实。

### 4.6 外观

- 珍珠白浅色主题和石墨黑深色主题；
- 持久化主题、左右面板宽度、折叠状态、Shell 展示数量、每行数量和行高；
- 工作台绘制前加载偏好，避免主题闪烁；
- 无效或越界尺寸恢复为文档规定的默认值。

## 5. 架构设计

### 5.1 Renderer 职责

WorkbenchView.vue 继续作为页面组合根，但拆分为职责单一的功能模块，不能继续膨胀为持久化层或业务逻辑层。

计划中的 renderer 模块：

- components/workbench/WorkbenchSessionSidebar.vue：聊天列表与日期分组；
- components/workbench/ShellCanvas.vue：标签、网格、布局、最大化和右键菜单；
- components/workbench/ShellHistoryDialog.vue：历史列表与预览；
- components/chat/GlobalChatPanel.vue：头部、驾驶模式、上下文、消息流和输入区；
- components/chat/CommandPlanCard.vue：多目标命令编辑、批准、拒绝和执行结果；
- stores/chat-workspaces.ts：当前聊天以及实时/历史视图协调；
- stores/layout-preferences.ts：与设置 IPC 同步的界面状态；
- views/settings/*：原型中每个设置区域对应一个独立组件。

Renderer 只能调用类型化 preload API，不能直接读写文件、访问密钥、调用模型地址或推断权威会话状态。

### 5.2 主进程服务

计划中的主进程模块：

- chat/chat-repository.ts：原子持久化聊天元数据和消息；
- chat/chat-service.ts：创建、列表、更新标题、驾驶模式和关联 Shell；
- chat/chat-runtime.ts：模型上下文、流式响应、压缩和异步竞态控制；
- chat/chat-router.ts：选择 LLM/VLM 调用路径；
- chat/token-estimator.ts：确定性上下文估算；
- shell-history/shell-history-repository.ts：有上限的脱敏终端历史和审计记录；
- shell-history/shell-history-service.ts：关闭、重连和历史查询协调；
- agent/multi-session-plan-service.ts：通过现有确认与围栏服务验证并执行多主机候选命令；
- settings/model-profile-service.ts：多个 LLM/VLM 配置及激活状态；
- settings/workbench-preferences-service.ts：主题、布局、模型路由和主机记忆偏好；
- 扩展 facts/host-facts-service.ts：列表、编辑、删除和采集策略。

每个文件只承担一个仓库、服务、设置面板或状态转换职责。通过窄接口适配现有大模块，不进行与本目标无关的重构。

### 5.3 持久化文件和密钥

在 Electron userData 下保存：

- chat-workspaces.json：聊天元数据、消息、摘要、Shell 关联和驾驶模式；
- shell-history.json：有上限的 Shell 历史与命令审计；
- model-profiles.json：不含密钥的 LLM/VLM 配置及激活 ID；
- workbench-preferences.json：主题、布局、模型路由和主机记忆设置；
- 现有主机事实文件：迁移为带版本结构。

所有仓库都必须进行结构校验，保存版本号，使用临时文件原子替换，串行排队写入，并在数据损坏时安全失败。API Key 继续按配置 ID 保存到受保护的密钥仓库；SSH 凭据继续留在现有安全存储中。

### 5.4 类型化 preload 域

Preload API 增加独立命名空间：

- chats：列表、创建、读取、发送、压缩、设置驾驶模式、删除和聊天事件；
- shellHistory：列表、读取、重连和历史事件；
- settings.models：配置增删改查、测试、激活和路由；
- settings.memory：选项、列表、读取、更新和删除；
- settings.appearance：读取和保存；
- agent：在兼容现有方法的同时增加多主机批准/拒绝。

每个 IPC handler 必须先验证可信发送方，再使用严格 Zod schema 校验输入，最后调用服务。事件必须携带聊天 ID 和运行 ID，renderer 必须忽略过期事件。

## 6. 状态与数据流

### 6.1 发送聊天消息

~~~text
输入区 -> chats.send(chatId, text)
       -> 校验并持久化用户消息
       -> 构建脱敏后的多 Shell 上下文
       -> 路由到激活的 LLM/VLM 配置
       -> 发送带 chatId/runId 的流式增量事件
       -> 解析 AI 回复和可选多主机命令计划
       -> 持久化 AI 消息与命令计划
       -> 更新聊天标题和上下文用量
       -> renderer 只应用匹配 chatId/runId 的事件
~~~

### 6.2 批准命令计划

~~~text
CommandPlanCard -> agent.approvePlan(chatId, planId, editedCommands)
                -> 校验计划归属和待处理状态
                -> 分别确认每条候选命令
                -> 分别执行正则围栏检查
                -> 将允许的命令发送给对应 Shell
                -> 持久化每台主机的审计结果
                -> 发送一次幂等的计划更新事件
~~~

### 6.3 会话生命周期

~~~text
SSH 打开 -> 关联到当前实时聊天 -> 按需显示主机记忆告知
SSH 数据 -> 实时 xterm 缓冲区 + 有上限的历史采集器
SSH 关闭 -> 完成脱敏 Shell 历史 -> 保留历史关联
重新连接 -> 根据安全描述建立真实会话 -> 关联新会话 -> 写入审计记录
~~~

## 7. 错误处理与安全

- 发送聊天前必须存在激活且可用的模型配置；
- 模型、仓库和压缩错误显示安全中文提示并提供重试；
- 多主机部分失败必须分别显示每个目标结果；
- 发送、批准、拒绝、关闭、重连和压缩通过请求 ID 保证幂等；
- 过期异步响应不能覆盖当前聊天、CMDB 选择、配置编辑器或历史预览；
- Renderer 只能显示纯文本或经过净化的 Markdown，禁止任意 HTML/脚本；
- 终端历史在持久化或进入模型上下文前必须经过现有敏感信息检测与脱敏；
- 设置和错误消息必须隐藏 API Key、Bearer Token、密码、私钥路径（需要时）以及 AccessClient 临时路径；
- 删除聊天只删除其消息和关联，不得在没有额外明确确认时关闭与其他聊天共享的实时 SSH；
- 仓库损坏时备份原文件并报告错误，不能静默覆盖不可读取的数据。

## 8. 可访问性与视觉对齐

- 保持 V18 的信息层级、标签、间距、状态和两套主题；
- 聊天列表、主机标签、连接方式和设置导航必须提供正确的选中语义；
- 对话框锁定焦点，关闭后恢复触发焦点，并在安全时支持 Escape；
- 分隔条提供 separator 角色、当前值和键盘调整能力；
- 流式消息使用非打断式实时区域，审批和错误变化可被辅助技术感知；
- 图标操作使用现有图标体系、工具提示和稳定的 30-32px 点击区域；
- 1440x900 和 1024x768 下不得出现无意义重叠或页面级横向滚动；
- 最长聊天标题、主机名、模型名、命令和路径不得撑坏控件尺寸；
- 历史/断开状态必须保持可读，不能对终端内容使用低对比度整体滤镜。

## 9. 数据迁移

已有安装可能包含一个旧模型配置和旧版主机事实数据。

- 旧模型配置只迁移一次，成为第一个激活的 LLM 配置，并保留受保护的 API Key；
- 现有正则围栏规则保持不变；
- 现有主机事实迁移到带版本的记忆结构，不删除字段；
- 迁移时不创建虚假聊天或历史记录；
- 应用启动时已经存在的实时会话关联到恢复的实时聊天；如无聊天则建立空聊天，但不重新连接；
- 迁移过程必须幂等，并使用固定测试数据覆盖。

## 11. 交付顺序

完整范围拆成可测试的纵向增量，但最终必须整体交付：

1. 持久化聊天工作区、左侧导航、布局偏好和实时 Shell 关联；
2. Shell 画布控制、Shell 历史、回放、复制和重连；
3. 全局聊天运行时、流式消息、上下文用量和压缩；
4. 多主机命令计划、审批、全自动模式和执行审计；
5. 模型路由以及完整 LLM/VLM 配置管理；
6. 主机记忆告知、配置、增删改查，以及完整安全围栏和外观设置；
7. 数据迁移、可访问性、完整回归、视觉验收和 Windows 安装包。

每个增量都必须形成可运行软件、聚焦测试和独立提交。现有 V18 SSH 功能必须在每个检查点保持可用。

## 12. 明确不包含的内容

只有经确认不属于 V18 原型的外部依赖不在本轮实现：

- 猜测或伪造某个专有 CMDB、堡垒机供应商协议或业务目录；
- 云端同步或多人协作；
- V18 HTML 中不存在的独立图片编辑器、自由绘图工具；
- 保存或回放原始敏感凭据；
- 为方便生产操作而绕过安全围栏或审批。

缺少真实 CMDB 提供方不影响 UI 完整对齐：两种堡垒机方式必须具有完整不可用、错误状态，密码和私钥直连继续完整可用。

## 13. 完成定义

只有满足以下全部条件，才能声明 V18 原型完整实现：

1. V18 HTML 中每个交互控件都有对应的真实 Vue/Electron 行为，或真实且明确的提供方不可用状态；
2. 左侧聊天导航、中间 Shell 画布、右侧全局 AI 聊天和六个设置页面都使用真实数据，并可持久化与恢复；
3. 原有 SSH、AccessClient、桥接程序、终端、Agent、安全围栏和已保存会话测试继续通过；
4. 不把原型示例运维数据作为用户数据写入产品；
5. 单元测试、集成测试、Electron E2E、lint、类型、构建和视觉几何检查全部从干净状态通过；
6. 从最终提交生成新的 Windows 安装包和匹配的 putty.exe；
7. 验收清单把 V18 中每个稳定操作、ID 映射到自动化测试或明确的人工检查。
