# Terminal-Agent 产品蓝图单页设计说明

## 目标

制作一张用于向领导汇报的独立 HTML 页面。页面说明 Terminal-Agent 为什么要从“分析环境的 Agent”演进为“嵌入系统管理员终端工作流的 Agent”。页面必须准确呈现当前产品蓝图，不把未规划能力、尚未完成的交付、通用兼容性或绝对安全写成既成事实。

## 核心叙事

页面开头是最重要的信息，依次表达以下四点：

1. 自动巡检已经体现出实际价值：Agent 能承担明确的检查工作，减少管理员的重复操作。
2. 现有告警分析 Agent 具备基于 ReAct 的环境理解、推理与分析能力。这是新方向的基础，而不是要被丢弃的旧方案。
3. 告警分析仍停留在管理员实际终端工作流之外。新的产品蓝图会把这些能力融入终端工作台，使 Agent 能围绕用户给出的目标参与工作。
4. 执行能力以明确的驾驶模式和本地安全控制为前提。页面应准确描述这些机制，不承诺绝对安全。

## 页面范围

页面只呈现 V2 产品设计中的下列能力：

- 三种连接入口：用户名 + 密码、私钥、AccessClient 兼容启动。
- SSH 终端会话、会话标签和多主机九宫格工作台。
- 新建连接后的自动只读观察。
- 按主机名关联的结构化主机事实库。
- 基于用户目标、当前会话和相关主机事实的目标驱动 AI 调度。
- 默认的辅助驾驶，包括变更命令的人机确认。
- 用户明确升级当前会话后才启用的全自动驾驶。
- 辅助驾驶下针对未确认命令的本地正则安全围栏。

页面不宣称结果验证闭环、对所有软硬件控制系统的通用兼容、完成度指标、超出上述驾驶模式的自动操作，或绝对安全。

## 页面结构

### 1. 开头：为什么要做这件事

使用简洁标题和三段短文。说明自动巡检表明用户认可能够分担实际工作的 Agent；现有基于 ReAct 的告警分析能力是有效基础；当前蓝图的目标是将它带入系统管理员正在使用的终端环境。

### 2. 产品蓝图

用一条横向流程展示：

`连接入口 -> SSH 终端与多主机工作台 -> 只读观察 -> 主机事实 -> 目标驱动调度 -> 按驾驶模式执行`

每个环节只配一句基于产品设计的说明。这条流程用于解释架构关系，不表示功能交付状态或实施时间表。

### 3. 安全优先

用一个清晰但克制的区域说明现有安全设计：

- 默认使用辅助驾驶。
- 用户确认只绑定当前会话和一条精确的候选命令。
- 辅助驾驶下，本地正则安全围栏会拦截命中的未确认命令。
- 全自动驾驶需要用户明确为当前会话升级。
- 密码、私钥和临时连接参数不会进入主机事实或 AI 上下文。

### 4. 收束

强调产品方向：保留已有 ReAct 环境理解和分析能力，将其放入真实终端工作流，使 Agent 能在安全边界内逐步承担更多系统管理员的工作。

## 视觉方向

- 一张干净的汇报单页，便于在领导沟通中快速阅读。
- 浅色中性背景、深炭灰文字，以克制的青绿色和蓝色突出重点；辅助驾驶确认使用少量琥珀色提示。
- 不使用渐变、数据大屏、装饰性插图或营销式表述。
- 中部流程是视觉重点。页面各段以自然的全宽区域承载；只有蓝图中的单个步骤使用紧凑模块。
- 在窄屏上保持流程顺序和文字层级清晰可读。

## 验收标准

1. 开头清楚说明从自动巡检和基于 ReAct 的告警分析，到终端嵌入式产品蓝图的演进逻辑。
2. 页面展示的每项能力都能对应 V2 产品设计。
3. 页面准确区分辅助驾驶与全自动驾驶。
4. 安全表述使用具体控制机制，不承诺绝对安全。
5. 页面为单个独立 HTML 文件，不依赖网络资源。
