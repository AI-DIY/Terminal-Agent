# 开源 Terminal-Agent 微调设计

## 背景

本轮修改依据《开源TA修改意见.pdf》，目标是在保留现有 SSH、堡垒机桥接、Shell 工作区、AI 工作区、模型配置、安全围栏、受保护凭据存储和总体布局的前提下，完成一组局部微调，并生成可供测试的 Windows 安装包。

本次实现使用 `codex/open-source-ta-polish` 分支，发布版本为 `1.0.9`。不重做工作台架构，不改变现有主区域布局，也不引入完整日志平台。

## 最终范围

本轮包含以下功能：

1. 工作台右上角新增独立的 `DevTools` 和 `Node Inspector` 入口；
2. 显式支持 `Ctrl+Shift+I` 打开独立的渲染进程 Chrome DevTools；
3. `Node Inspector` 由 Terminal-Agent 自动启动并在独立 Electron 窗口中附加主进程，不打开外部浏览器，也不要求用户手动复制地址或选择调试目标；
4. 从模型输入和模型回复显示链路中移除自动脱敏，同时保留本地凭据保护和命令执行控制；
5. 将用户界面的“聊天”任务入口改为“任务”，实现默认命名、首次使用后的自动改名、手动重命名、置顶和取消置顶；
6. 将大语言模型和视觉语言模型连接列表的内容明确调整为左对齐；
7. 将任务历史区滚动条调整为参考 Gemini 的低干扰样式；
8. 更新测试、说明文档和发布元数据，并构建 `1.0.9` Windows 安装包。

## 明确不做

- 不新增“查看日志”按钮、日志窗口、日志持久化或全业务日志埋点；现有桥接诊断日志和现有错误处理继续保留；
- 不新增多命令候选、命令组删除、整组审批或批量执行；现有单条候选命令、一次性确认和安全围栏保持不变；
- 不实现旧任务数据迁移，不识别或转换旧的 `新建聊天 <时间>` 标题，也不兼容旧任务文档中的标题状态和置顶状态；使用新版前由用户清空旧任务数据；
- 不删除模型 API Key、SSH 密码、私钥、私钥口令或堡垒机临时密码的本地保护；
- 不改变任务历史区宽度、Shell 工作区结构、AI 工作区结构、设置页导航或 Windows 原生窗口按钮；
- 不把任何调试工具嵌入主窗口内部。

## 方案选择

诊断能力采用“两个按需打开的独立调试窗口”：渲染进程使用 Electron 自带的分离 DevTools，主进程使用 Node Inspector 和 Electron 内置 DevTools 前端。两个窗口均由主进程创建、复用和回收。

未选择以下方案：

- 不使用 `chrome://inspect` 或系统浏览器，因为这会要求用户切换应用、查找目标并手动附加；
- 不把 DevTools 或 Inspector 停靠在工作台中，因为会挤占现有页面和位置；
- 不建设统一日志中心，因为用户已明确以开发速度为优先并取消日志功能。

任务元数据采用显式状态，而不是根据标题文字反推行为。每个新任务持久化标题状态和可选置顶时间；自动改名只作用于系统生成且尚未开始的任务，手动标题不会被后续活动覆盖。

模型内容采用“模型链路原文直通、本地凭据继续保护”的边界。Terminal-Agent 不再在请求模型之前替换任务文本，也不再在展示模型回复之前二次替换或拒绝内容；但凭据存储、Shell 历史和桥接日志仍遵守原有本地保护规则。

## 独立渲染进程 DevTools

工作台右上角在“设置”右侧新增 `DevTools` 按钮。点击按钮时，主进程对当前主窗口的 `webContents` 调用分离模式 DevTools：

- 使用 `openDevTools({ mode: 'detach', activate: true })`；
- 已打开时不创建第二个实例，只恢复并聚焦现有 DevTools 窗口；
- 关闭 DevTools 不影响主窗口和正在运行的 SSH/AI 会话；
- 主窗口关闭时，关联的 DevTools 随 `webContents` 一并关闭。

由于应用已移除 Electron 默认菜单，主进程必须在主窗口 `webContents` 的 `before-input-event` 上显式处理 `Ctrl+Shift+I`。快捷键与按钮调用同一个诊断控制器，行为完全一致，并调用 `preventDefault()`，避免按键继续传入页面或活动终端。

该快捷键在工作台、设置页和模态框打开时均有效。它只针对 Terminal-Agent 主渲染进程，不接受渲染层传入任意 `webContents` ID。

## 自动附加的主进程 Node Inspector

工作台右上角在 `DevTools` 右侧新增 `Node Inspector` 按钮。点击后由主进程完成全部连接步骤：

1. 检查当前进程是否已经启用 Node Inspector；
2. 如果已有 Inspector 地址，则复用该地址，并记录它不是由本次窗口创建；
3. 如果尚未启用，则通过 `node:inspector` 在 `127.0.0.1` 和随机可用端口上按需启动；
4. 读取主进程 WebSocket 调试地址；
5. 创建独立 `BrowserWindow`，加载当前 Electron/Chromium 自带的 Node 调试前端，并把目标 WebSocket 地址作为固定参数自动附加；
6. 窗口显示后即可使用控制台、源码、source map、调用栈、断点、作用域变量、CPU 性能分析和内存工具。

Inspector 窗口使用独立的窗口生命周期：

- 重复点击按钮时恢复最小化状态并聚焦现有窗口；
- 不启动外部 Chrome，不打开 `chrome://inspect`，不复制地址到剪贴板；
- Inspector 只绑定 `127.0.0.1`，不得监听 `0.0.0.0` 或局域网地址；
- 窗口关闭时，如果 Inspector 是本功能按需启动的，则关闭该 Inspector；如果应用原本通过 `--inspect` 启动，则只关闭前端窗口，不关闭外部拥有的 Inspector；
- 主窗口或应用退出时关闭 Inspector 前端窗口，并清理由本功能启动的 Inspector；
- 开发态和打包态都使用 Electron 当前版本携带的调试前端，不依赖系统 Chrome 的安装路径或登录状态。

主进程提供两个无参数、受信任来源校验的 IPC 命令：打开渲染 DevTools、打开 Node Inspector。渲染进程不能提供 URL、端口、WebSocket 地址或任意调试目标。

## 顶部工具栏布局

应用按钮顺序为 `设置`、`DevTools`、`Node Inspector`，其右侧继续保留 Windows 原生最小化、最大化/还原和关闭按钮区域。

- 三个按钮沿用现有顶部栏高度、边框、字号和图标风格；
- 使用 Lucide 图标，不手绘 SVG；
- 顶部栏仍为原生窗口按钮预留固定右侧空间；
- 在受限宽度下，诊断按钮隐藏文字但保留固定尺寸图标按钮和工具提示；
- 错误消息不得把按钮或当前任务标题推入原生窗口按钮区域；
- 不改变工作台主体的三栏结构和尺寸。

## 模型输入与回复原文直通

### AI 工作区

全局 AI 工作区执行以下调整：

- 用户输入在去除提交所需的首尾空白后原样持久化、原样显示并原样发送；
- 历史用户消息和模型回复原样加入后续模型上下文；
- Shell 显示元数据、已获授权且已经由主机记忆系统采集的结构化事实、近期已批准命令审计不再经过发送模型前的二次文本脱敏；
- 系统提示词删除“只使用脱敏消息”和关于脱敏内容的说明；
- 模型流式增量与最终回复原样传给渲染进程并原样显示；
- 不再因临时路径、`.ssh` 路径、令牌形态文本、长 Base64 文本或凭据关键词而替换整段内容。

### Shell 工作区 AI 辅助代理

Shell 工作区代理执行相同边界：

- 目标、主机名和已采集结构化主机事实不再经过发送模型前的二次脱敏；
- 系统提示词删除“不得索取、推测或输出密码、私钥、API Key、令牌”等与本轮脱敏功能相关的限制；
- 保留中文输出、严格 JSON 结构、分析、证据策略和单条候选命令格式；
- 模型流式内容、最终分析、证据策略、候选命令及说明不再二次脱敏，也不再仅因内容匹配敏感模式而拒绝整条提案。

### 继续保留的保护

取消模型链路脱敏不改变以下能力：

- 模型 API Key 仍由 Windows 受保护存储保存，不写入普通配置，不通过渲染 DTO 回填；
- SSH 密码、私钥正文和私钥口令仍不写入任务数据或普通连接配置；
- 堡垒机桥接临时密码仍不写入 `putty-bridge.log`；
- Shell 历史继续保护密码提示后的输入和已识别凭据；
- 模型连接错误和基础设施错误继续避免回显应用持有的 API Key 或 SSH 凭据；
- 主机记忆的授权、采集范围和本地持久化过滤保持不变；本轮只移除从已获授权数据到模型请求之间的二次脱敏；
- 安全围栏、辅助驾驶、候选命令精确匹配、一次性确认、确认有效期和自动驾驶会话授权保持不变。

README 必须明确提示：Terminal-Agent 不再自动脱敏发送给模型的任务上下文，用户应只配置其信任的本地模型或集团内网模型。模型连接指向公网服务时，应用不新增阻断弹窗。

## 任务命名与状态

用户可见文案统一使用“任务”：

- “新建聊天”按钮改为“新建任务”；
- 新建失败、读取失败、空列表等用户可见文案中的“聊天”按语义改为“任务”；
- 内部模块、类型和 IPC 可以继续保留 `chat` 命名，避免无意义的大范围重构。

新任务默认标题使用现有的上海时区与时间格式：

```text
新建任务 YYYY-MM-DD HH:mm:ss
```

任务持久化以下元数据：

- `titleState`: `new`、`started` 或 `custom`；
- `pinnedAt`: ISO 时间或空值；
- `createdAt` 与 `updatedAt` 继续分别表示创建时间和真实任务活动时间。

系统标题中的时间始终取任务 `createdAt`，自动改名后时间部分不变化。

## 首次活动自动改名

标题状态为 `new` 时，以下任一操作首次成功持久化后，在同一主进程写入队列中将任务改为：

```text
任务 YYYY-MM-DD HH:mm:ss
```

触发条件为：

- AI 工作区成功持久化第一条用户消息；
- Shell 工作区成功持久化第一个 Shell 关联。

仅编辑草稿、打开连接窗口、连接失败、模型请求开始但用户消息未能保存，均不触发自动改名。并发发生 AI 消息和 Shell 接入时，持久化队列只完成一次状态转换。

用户手动重命名后，`titleState` 变为 `custom`；以后的 AI 消息或 Shell 接入不得覆盖自定义标题。

## 重命名、置顶与取消置顶

任务列表项右侧原有的单独删除按钮改为三点菜单，包含：

- `重命名`；
- `置顶` 或 `取消置顶`；
- `删除`。

重命名在任务标题位置使用行内输入框：

- 进入编辑时选中现有名称；
- `Enter` 保存，`Escape` 取消；
- 失焦保存，但菜单切换和任务切换不得产生重复请求；
- 保存前去除首尾空白；
- 空名称不保存并显示就地错误；
- 最大长度为 255 个字符；
- 保存成功后退出编辑状态，保存失败时保留输入值供用户修正。

置顶操作写入新的 `pinnedAt`。任务列表顶部新增“置顶”分组：

- 所有已置顶任务只出现在“置顶”分组；
- 最近置顶的任务排在最上方；
- 同一置顶时间发生冲突时使用任务 ID 稳定排序；
- 取消置顶后任务返回原日期分组；
- 普通日期分组继续按任务真实 `updatedAt` 排序；
- 置顶和取消置顶不得改变 `updatedAt`，避免把管理动作伪装成任务活动；
- 删除任务时其置顶元数据随任务一起删除。

任务标题和置顶操作由主进程验证与持久化。渲染进程通过受信任 IPC 发送任务 ID、请求 ID 和目标值；成功响应和既有 `chats:changed` 事件驱动所有视图同步。

## 任务数据版本边界

新版任务文档包含 `titleState` 和 `pinnedAt`，并采用新的持久化版本。按照用户明确要求，本轮不提供旧数据迁移或兼容读取：

- 不推断旧标题是系统标题还是用户标题；
- 不为旧任务补写标题状态或置顶状态；
- 不保留旧任务文档 schema 的读取分支；
- 测试和安装验收从空任务数据开始。

如果未清空旧任务数据，新版应返回明确的“任务数据版本不兼容”错误，不得静默丢弃、覆盖或猜测转换旧数据。

## 模型连接列表左对齐

“大语言模型配置”和“视觉语言模型配置”共用相同规则：

- 左侧连接列表的模型名称、提供方与模型名称、密钥状态从左上角开始排列；
- `.profile-select` 明确设置占满可用宽度、`text-align: left`、`justify-items: start` 和 `align-content: start`；
- 覆盖通用按钮的水平居中布局，不依赖浏览器默认样式；
- 已激活状态和现有操作区保持原位置；
- 不修改设置页网格宽度、字段顺序和响应式断点；
- 珍珠白和石墨黑主题使用同一几何规则。

## Gemini 风格任务历史滚动条

滚动条只调整任务历史列表，不影响 Shell、设置页或其他对话框。

- 轨道始终透明，不显示上下箭头；
- 列表未悬浮且未包含键盘焦点时，滑块透明或近乎不可见；
- 鼠标进入任务历史列表或键盘焦点进入列表时，显示细窄的中性灰色圆角滑块；
- 滑块自身悬浮时颜色略微加深；
- 使用稳定的滚动条占位，显隐不导致任务标题横向跳动；
- Chromium 使用 `::-webkit-scrollbar` 伪元素，Firefox 使用 `scrollbar-width` 和 `scrollbar-color`；
- 颜色从当前主题的中性色变量组合，不引入只适合单一主题的固定亮色。

## 错误处理

### 诊断窗口

- 诊断 IPC 必须校验调用方是当前主窗口；
- Inspector 启动失败、地址不可用、内置调试前端加载失败或窗口已销毁时，返回稳定的可展示错误；
- 工作台顶部以非阻塞方式显示错误，不关闭 SSH、AI 或设置流程；
- 创建部分成功后发生失败时，关闭新建窗口并关闭本功能拥有的 Inspector，避免残留端口；
- 诊断窗口关闭和应用退出清理必须幂等。

### 任务操作

- 重命名和置顶请求使用请求 ID 保证重复提交幂等；
- 主进程持久化成功后才发布任务变化；
- 自动改名和业务操作在同一串行写入中完成，避免只保存其中一半；
- 置顶写入失败不改变渲染排序；
- 重命名失败保留行内输入，允许用户修正或取消；
- 旧任务数据存在时显示版本不兼容错误，不自动覆盖文件。

### 模型内容

- 原文直通不取消 schema、最大长度、超时、取消、并发所有权和持久化错误处理；
- 模型返回无效 JSON 时，Shell AI 代理继续拒绝该结构，但不再因为文本类似凭据而拒绝合法结构；
- API Key 和 SSH 凭据相关基础设施错误继续使用安全的公开错误信息。

## 测试策略

实现过程遵循测试驱动开发，先写失败测试，再编写最小实现。

### 单元与契约测试

1. 诊断控制器：分离 DevTools 参数、重复打开聚焦、Inspector 环回随机端口、已有 Inspector 复用、自动附加 URL、窗口关闭和资源归属清理；
2. 快捷键与 IPC：`Ctrl+Shift+I` 只触发一次、阻止默认传播、只接受受信任主窗口、渲染层不能传入目标地址；
3. 任务仓库：新默认标题、AI 首消息自动改名、首个 Shell 自动改名、并发只改一次、自定义标题不覆盖；
4. 任务管理：重命名验证与幂等、置顶时间、取消置顶、不修改任务活动时间、置顶排序和日期分组；
5. 数据版本：新文档可读写，旧文档明确报版本不兼容，不存在迁移路径；

## 验收标准

- `DevTools` 按钮和 `Ctrl+Shift+I` 均打开独立的渲染进程 Chrome DevTools；
- `Node Inspector` 按钮打开独立 Electron 窗口并自动附加主进程，无需外部浏览器或人工选择目标；
- 两个调试窗口重复打开、关闭和应用退出行为稳定，Inspector 不向局域网开放；
- 工作台不出现“查看日志”按钮或新日志功能；
- 模型请求与模型回复显示链路不再自动脱敏，相关系统提示词不再声称上下文已脱敏；
- API Key、SSH 凭据、桥接临时密码和 Shell 历史本地保护继续有效；
- 新任务按指定格式命名，首次 AI 消息或首个 Shell 后自动改名，自定义名称不会被覆盖；
- 用户可以重命名、置顶和取消置顶任务，状态重启后保留，置顶不篡改任务活动时间；
- 不存在旧任务数据迁移代码，旧任务文档得到明确的不兼容错误；
- 大语言模型和视觉语言模型连接内容明确左对齐；
- 任务历史区滚动条在未悬浮时低干扰、悬浮或聚焦时清晰可用，且不引发布局位移；
- SSH、堡垒机桥接、Shell、模型路由、安全围栏、辅助驾驶、自动驾驶和单候选命令审批无回归；
- 所有自动化、视觉和打包后验证通过，并生成可供测试的 `1.0.9` Windows 安装包。
