# Terminal-Agent v3.0.0 SSO Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Terminal-Agent v3.0.0 with a default-on single sign-on gate that passively captures the platform's natural user-info response, keeps the verified identity in runtime memory, and protects built-in skills until authentication succeeds.

**Architecture:** Keep the local Electron renderer as the only application UI. A main-process SSO service owns the `.ta/user-config` document, the temporary authentication `BrowserWindow`, the CDP `Network` listener, the authentication state machine, and the safe state snapshot sent to the trusted renderer. The renderer consumes only the narrow preload SSO API; it never receives the remote login DOM, cookies, request IDs, headers, or raw response bodies. Existing workbench/settings/skills views remain the same application shell, with `App.vue` becoming the page gate.

**Tech Stack:** Electron 43, Vue 3, TypeScript, Zod, Vitest, Playwright Electron tests, Electron CDP debugger APIs, Electron-builder/NSIS, and the existing `AtomicJsonStore` persistence helper.

**Spec:** `docs/superpowers/specs/2026-09-03-sso-login-design.md`

## Global Constraints

- SSO is enabled by default; a missing or incomplete enabled configuration must force `设置 → 单点登录` and must never expose the workbench.
- The configuration file is exactly `%USERPROFILE%\\.ta\\user-config` on Windows and `<app.getPath('home')>/.ta/user-config` elsewhere; it has no `.json` suffix.
- The persisted document is version 1 and has the exact top-level shape `{ "version": 1, "sso": { ... } }`.
- `platformUrlMatcher` and `userInfoUrlMatcher` both support `exact` and `regex`; exact matching compares normalized `protocol + host + pathname` and ignores query, while regex matching uses the fragment-free full URL and retains query.
- `employeeIdField` and `nameField` support safe Object Path/JSONPath forms such as `data.em[0].name`, `$.data.em[0].name`, and `$['data']['em'][0]['employeeId']`; wildcard, recursive, filter, script, multi-value, and prototype-polluting paths are rejected.
- After platform navigation, Terminal-Agent only listens to the platform's natural network response. It must not issue `fetch`, `session.fetch`, `net.request`, a replay, a DOM/localStorage fallback, or an additional user-info request.
- A matching response is read only after the same `requestId` emits `Network.loadingFinished`; response bodies are size-limited, JSON-parsed, and discarded after identity extraction.
- Authentication identity is runtime-only. Cookies live only in a non-persistent authentication session; no identity, cookie, token, password, authorization header, request ID, raw URL query, response body, or complete HTTP headers are persisted or exposed to the renderer.
- `skillsAvailable` is true only for `authenticated`; `login-disabled` is intentionally untrusted and cannot enable skills. Ordinary chat, SSH, settings, and other local workbench capabilities remain available when the gate is disabled.
- Every main-process IPC handler verifies `event.sender === mainWindow.webContents`; preload exposes only validated, frozen SSO methods.
- The disabled-gate warning text is exact: `关闭登录门控后，应用将以未登录状态运行，内置技能不可使用。`
- The authenticated welcome text is exact in structure: `欢迎回来，<姓名>（<工号>）`; the SSO identity takes precedence over the local display-name preference.
- The release branch is `codex/v3.0.0`, the package version is `3.0.0`, and the `v3.0.0` tag is created only after fresh tests, lint, build, E2E, and release checks pass.
- No new runtime dependency is added for JSON path parsing or URL matching; use small, unit-tested local modules.
