Terminal-Agent 01 / 产品转折

为什么要从“分析”走向“真正干活”

从“会分析”，到“在终端里真正干活”

自动巡检已经体现出实际价值：当 Agent 能承担明确的检查工作、减少重复操作时，才能真正融入管理员的日常工作。

已有价值

自动巡检在分担工作

系统管理员需要的，不只是信息和建议，而是能减少重复劳动、可以长期使用的协作能力。

已有基础

告警分析提供理解能力

告警分析 Agent 具备 ReAct 的环境理解与推理基础，但它还主要停留在终端之外分析问题。

当前方向

把 Agent 放进终端现场

将已有分析能力融入管理员正在使用的终端，让 Agent 围绕目标参与实际工作，并保留明确的安全控制。

终端之外的分析与建议 → 终端之内、受控参与实际工作
不是重新做一个 Agent，而是在已有 ReAct 能力基础上，把它放进系统管理员的一线工作环境。
Terminal-Agent 02 / 当前产品设计

面向真实终端工作流

Terminal-Agent 当前产品设计

围绕连接、环境理解、目标协作和执行控制，形成一套嵌入终端的工作台。

01

进入终端工作现场

支持用户名 + 密码、私钥和 AccessClient 兼容启动；提供 SSH 会话、标签与多主机工作台。

02

理解主机环境

新建连接后进行只读观察，按主机名沉淀软件、进程、服务和日志位置等结构化事实。

03

围绕目标协作

Agent 结合用户目标、当前会话和主机事实，安排需要收集的信息与后续操作步骤。

04

两种驾驶模式

辅助驾驶默认启用；用户明确为当前会话升级后，才进入全自动驾驶。

05

安全控制

精确命令确认、本地正则安全围栏和敏感信息隔离，共同约束 Agent 的执行边界。

执行原则

辅助驾驶下，查询和观察可执行，变更命令需要用户确认；全自动驾驶仅在用户明确升级当前会话后启用。

产品重点不是增加一个分析入口，而是让 Agent 在清晰的安全边界内，逐步分担系统管理员的工作。
