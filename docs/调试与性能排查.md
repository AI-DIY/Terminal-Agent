# Terminal-Agent 调试与性能排查

## DevTools 与 IPC

在工作台右上角打开 `DevTools`，或按 `Ctrl+Shift+I`。打开动作会临时启用 IPC 时序日志；在 Console 中用 `[TA IPC]` 过滤即可查看每一条调用的关联编号、通道、完成或失败状态和往返耗时。

日志刻意不写入请求参数、响应内容、终端输入、文件路径、密钥或错误原文。它用于确定是哪一个 IPC 边界变慢或失败，而不是用于导出业务数据。

诊断结束后，可在渲染器 DevTools Console 运行：

```js
window.terminalAgent.diagnostics.setIpcTracing(false)
```

`window.terminalAgent.diagnostics.isIpcTracingEnabled()` 可用于确认当前状态。关闭或重启应用后，追踪默认关闭。

## Node Inspector

右上角的 `Node Inspector` 会为主进程创建一个仅限 `127.0.0.1` 的 Inspector 窗口。它适合在主进程处理 IPC、SSH、SFTP、持久化或模型调用时设置断点并查看调用栈。该窗口关闭后由应用回收本次启动的 Inspector，不会把调试端口暴露给局域网。

排查一条请求时，先在 DevTools Console 确认 `[TA IPC #n]` 的通道和耗时，再在 Node Inspector 对应的 IPC handler 或服务方法设置断点。不要将含有私有终端输出、会话凭据或模型密钥的调试截图和日志发送到不受信任的位置。

## 性能复现

性能问题应在安装包或 `release\\win-unpacked` 中复现，而不是只观察开发服务器。优先录制以下短场景：鼠标划过工作台按钮、SSH 连续键入、AI 输入框连续键入，以及关闭 SSH 后历史列表刷新。DevTools 的 Performance 面板可用来确认长任务是否来自渲染、布局、IPC 往返或主进程持久化。

SSH 历史输入审计会在短延迟内合并连续按键，并在连接关闭前强制写入；这避免每次按键都触发完整的脱敏和历史处理，同时保留命令顺序和关闭后的历史记录。
